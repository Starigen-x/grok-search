# grok-search · 产品需求（PRD）

> 本文件用老板的语言写，不出现技术术语。老板可以直接改；改完说一句「PRD 更新了」即可，技术合伙人负责把变化落进功能台账。

## 一句话

给老板自己所有的 AI 客户端（电脑上的 Claude Code、手机和网页端的聊天客户端）提供一个统一的联网搜索服务：客户端里填上仓库地址（或网络地址）、密钥和模型名，就能让 AI 搜到最新的互联网信息，并且能查到答案的来源出处。

## 目标用户与场景

- 用户：老板本人，在多台设备、多个 AI 客户端上使用
- 场景 1：在 Claude Code 里问时事、行情、新产品动态，AI 通过本服务搜索并给出带来源的答案；追问「来源是什么」能拿到可点开核实的链接列表
- 场景 2：在手机或网页端的 AI 客户端里，同样填好配置后使用同一个搜索服务，不需要电脑开机
- 场景 3：给 AI 一个网址，让它读取全文并总结（论文、文档、新闻页）

## 必须有（第一版就要）

> 每条写「用户能做到什么」，不写怎么实现。

- 在客户端里只需配置三样东西：服务地址、密钥、模型名，就能用
- 搜索：提问后拿到基于最新网络信息的答案
- 来源：每次搜索都能查到这次答案参考了哪些网页，链接可点开核实（修复老版本「来源永远为空」的毛病）
- 读网页：给一个网址，拿到该页的完整正文（不再依赖 Tavily/Firecrawl 两家额外服务和密钥）
- 双形态：既能装在电脑里给桌面客户端用，也能作为网络服务跑起来给手机/网页端客户端用
- 出错说人话：密钥错了、网络不通、上游服务挂了，都给出能看懂的提示，而不是沉默或乱码

## 可以晚（记下来，先不做）

- 部署到老板的服务器上，手机/网页端真正远程连接使用（第一版先保证这个能力在本机验证通过；部署需要老板提供服务器信息）
- 发布到 Python 官方软件商店（PyPI），客户端配置从一长串地址变成一个短名字
- 给别人用的详细上手文档 / 双语文档

## 明确不做

> 防止范围膨胀；想改主意先改这里。

- 站点地图功能（整站页面结构梳理）——老板不用，砍掉
- 补充搜索源（Tavily / Firecrawl 额外参考结果）——不想继续维护这两家的密钥，砍掉
- 「搜索前六步计划」类流程工具——对第三方客户端没用还添乱，砍掉
- 修改客户端设置、切换全局模型之类管得太宽的工具——砍掉；模型在配置里定，不在对话里换
- 配置自检工具——砍掉，用清晰的报错信息代替

## 成功标准

- 老板的 Claude Code 换用新服务后，日常搜索无感切换、不变差
- 任何一次搜索后追问来源，都能拿到非空的、可点开的链接列表（老版本做不到）
- 新设备/新客户端接入：照着说明填三个配置项，5 分钟内能用
- 服务出问题时，第一条报错信息就能看出是密钥、网络还是上游的问题

## 参考与口味

- 现用的 GuDaStudio/GrokSearch（grok-with-tavily 分支）是出发点：喜欢它「填仓库地址就能装」的轻，讨厌它工具臃肿、来源功能坏、出错不吭声
- 口味：精简、可靠、错误透明，胜过功能堆砌
