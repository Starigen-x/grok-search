# 协作手册（迭代协议全文）

> 本手册是项目的法律，CLAUDE.md 是它的速记。修订本手册须向老板给一句白话理由并记入 CHANGELOG。
> 原则出处与设计理由见立项时使用的 new-project skill（references/playbook.md）；本文件自含，日常无需回读 skill。

## 1. 角色

- **老板 = 产品经理**：定需求、定优先级、验收成品；不做任何技术决策，不需要看代码
- **技术合伙人 = Claude 主会话**：全部工程职责——规划、实现、质检、文档、汇报；口号是「老板掌舵，我执行」

## 2. 功能循环（每个功能走一遍，顺序不可跳）

1. **取活**：docs/tasks.md 里最靠前且前置已完成的「待办」→ 状态改「进行中」（全表同时只许一个）
2. **对齐**：功能的产品行为若有多种合理理解 → 用选择题问老板（一次最多 3 问，只问产品问题）；L 规模功能必须先把「做完长什么样」写进台账验收列、老板点头再动工——返工最贵的形态是方向错了
3. **实现**：小步走，每到可运行状态就 commit（信息格式 `feat(#编号): 白话描述`）；技术知识产生即写入对应文档——写不进文档的共识等于不存在
4. **自检**（交付前逐条过）：
   - a. 质量门单命令全绿（见第 3 节）
   - b. 新逻辑有对应测试；对本功能守护的关键行为做一次变异自检——故意改坏实现、确认测试必然变红、再还原。不红说明测试是假的，先修测试
   - c. 对照台账验收标准逐条核对
   - d. diff 复查：无密钥、无越界改动（范围外问题 → tech-debt.md 记账）
5. **QA 评审**（M/L 规模必做，S 可免）：派一次性 qa-reviewer 子代理（定义在 .claude/agents/qa-reviewer.md）独立出具 PASS / FAIL+编号理由；FAIL → 返工后回到第 4 步。子代理用完即收，禁止留后台挂着。**熔断**：同一功能第 3 次 FAIL → 停下，用白话向老板说明卡点并给选项（简化需求 / 换做法 / 暂时搁置），老板拍板前不再硬试
6. **收尾**：tasks.md 状态改「待验收」；CHANGELOG.md 加一条白话记录；行为变化涉及的文档同步更新
7. **汇报**：按第 5 节模板向老板汇报；老板亲手验证点头后，状态改「完成」并移入归档区

**计划外来件（老板随时会提的新想法 / 需求变更 / 「坏了」）**

- 新想法与变更：翻译成台账新行（验收标准用白话跟老板确认）→ 问老板插队还是排队；默认不打断「进行中」的功能
- 缺陷：老板只需说清「我做了什么、看到了什么、本来期望什么」；缺陷默认插队优先修，**修复必须附带防复发测试**，修完记入 CHANGELOG
- 一切来件先落台账再动手——台账之外无工作

## 3. 质量门

- 单命令：`make check`（格式化检查 + lint + 类型检查 + 测试，缺哪样补哪样；报错信息里尽量内嵌修法提示）
- 全绿才许 commit；**禁止删除、跳过或改弱既有测试使其变绿**——确需修改测试语义，必须在汇报中向老板单独点名说明
- 冒烟标准：`make serve` 一条命令能把产品跑起来，随时可给老板演示

## 4. QA 子代理评审要点（qa-reviewer 的行为规范，完整定义见 .claude/agents/qa-reviewer.md）

- 不听主会话的自评结论，自己跑命令核实
- 验收标准逐条核对；质量门复跑；变异测试抽查 1–2 个关键行为（改坏实现→测试必须红→还原）
- 按 architecture.md 硬约束逐条扫描 diff；grep 密钥泄漏
- 只报影响正确性、验收标准或硬约束的问题，不做风格挑刺（防评审驱动的过度工程）
- 结论只有两种：PASS / FAIL+编号理由；末尾附 2–3 句给老板的白话摘要

## 5. 向老板汇报模板（每功能完成时；平时被问「什么情况」也用它）

```
【汇报】功能 #N：{{名称}}
- 做成了什么：{{一句白话，说用户能干什么了}}
- 你怎么验证：{{一步操作 + 预期看到什么}}
- 要注意的：{{风险 / 限制 / 花销；没有写「无」}}
- 下一步建议：{{下个功能 + 一句为什么}}
- 需要你拍板：{{产品选择题；没有写「无」}}
```

## 6. 会话与成本纪律

- **事件驱动，不设定时轮询**：订阅版提示缓存 TTL 已是 1 小时，无需为保缓存空转；老板说「继续」即接力
- 新会话恢复只按 CLAUDE.md 启动协议读台账与 CHANGELOG 尾部，不通读文档
- 长任务（批量重构、批量生成）放后台跑，跑完汇报，中途不占对话
- 子代理只用于两类事：① QA 评审（一次性）② 可并行的批量机械活；不为仪式感开子代理
- **断点纪律**：每个功能「收尾」完成即是安全断点——全部状态已在文件里，老板随时可关窗口，新会话说「继续」无损接力；感知上下文吃紧时不硬撑，收尾当前功能后主动建议老板换个新窗口继续
- 上下文自动压缩只当安全网，不当依赖：重要状态必须活在文件里，不能只活在对话里
- 连续开发模式：老板说「连着做完 M1」时，逐功能走完整循环（含 QA），全部到「待验收」后一次性汇报清单；途中上下文吃紧就停在最近的收尾断点先汇报

## 7. 承重审计（每个里程碑收口时做，流程只减不烂）

1. 逐条检查本手册与 CLAUDE.md 的规矩：它防的失败模式还存在吗？不存在就删——每条规矩编码一个对模型短板的假设，短板消失规矩就该撤
2. 盘 tech-debt.md：清账 / 降级 / 立项
3. 文档除草：过期内容删除或归档，交叉引用修正——文档只增不删必然膨胀失效
4. 收口标准：里程碑收口时产品必须处于「随时可给人试用」状态；正式发布/上架本身立为台账功能来做，不搞临时突击
5. 问老板一句：「流程哪里让你觉得烦？」——烦点就是下一条要拆的规矩
